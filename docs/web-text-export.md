# Тексты для PWA: способ поставки и ограничения

Текущий веб-экспорт сделан из локального SQLite-снимка
`ru-core-snapshot-2026-09-25.db`, собранного из фиксированной версии
[Totopolis/laws](https://github.com/Totopolis/laws) (`6bea74232fa644863e683030d381c7a5656dff00`).
Подробности технической сверки и контрольные суммы — в
[журнале аудита](totopolis-audit-2026-09-26.md).

Экспорт включает 37 документов, 10 807 статей и 10 877 фрагментов. Он
предназначен для отображения и не означает, что редакция проверена на текущую
дату. Тексты нуждаются в сверке с официальными публикациями и юридическом
редакторском ревью. Нет истории изменений и гарантий актуальности. ИИ пока
не использует фрагменты как источники.

Файлы устроены так:

- `mobile/src/data/ru-web-texts-manifest.json` — небольшой каталог карточек,
  загружаемый вместе с приложением;
- `mobile/public/legal-texts/totopolis-2026-09-25-v1/<id>/<page>.json` —
  отдельные страницы по 24 фрагмента, всего 471 файл (около 55 МБ до
  сжатия при передаче);
- `mobile/public/legal-texts/LICENSE.txt` — уведомление BSD-2-Clause
  источника, доступное вместе с опубликованной PWA.

Service worker не добавляет страницы текстов в начальный кеш. Он кеширует
прочитанную страницу при первом открытии. Кнопка на главной отдельно
скачивает все страницы для офлайна, не блокируя обычный быстрый старт.
Браузер/операционная система может впоследствии удалить этот кеш при нехватке
места. Рекомендуется сохранять тексты по Wi-Fi и проверять режим полёта перед
зависимым от интернета использованием.

Повторная сборка из уже проверенного локального SQLite-файла:

```powershell
python .\backend\scripts\export_web_texts.py
python .\backend\scripts\export_web_texts.py --check
npm run build
```

При новом источнике или редакции нужно изменить `VERSION` в экспортёре и
имя runtime-кеша в `mobile/workbox-config.cjs`, затем заново проверить
источник. Скрипт не скачивает данные сам и останавливается, если возникли
лишние файлы или неожиданное число документов.
