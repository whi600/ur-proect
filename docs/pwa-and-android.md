# Установка без ИИ-помощника: iPhone PWA и Android

## iPhone: PWA

PWA — это установленный через Safari сайт «ПравоОрбита». Он получает отдельную
иконку на главном экране, открывается без адресной строки Safari и не требует
Apple Developer Program или Expo Go.

### Что подготовлено

- `mobile/public/manifest.json` — имя, иконка и цвет PWA;
- service worker генерируется Workbox после каждой сборки;
- `mobile/dist/` — готовая статическая веб-сборка, не попадающая в Git;
- команда `npm run build:pwa` собирает PWA и service worker.

### Как проверить локально

```powershell
Set-Location 'C:\Users\User\Documents\ChatGPT\консультант плюс ( с ИИ)\mobile'
npm run build:pwa
npm run serve:pwa
```

Откройте указанный адрес в браузере. Остановить сервер: `Ctrl+C`.

### Как установить на iPhone

Для установки нужен HTTPS-адрес опубликованной PWA: iPhone не разрешает
обычному сайту по локальному `http://192.168...` полноценно использовать
service worker. После публикации `mobile/dist/` на HTTPS-хостинге:

1. Откройте адрес сайта в Safari на iPhone.
2. Нажмите «Поделиться».
3. Выберите «На экран Домой».
4. Подтвердите имя «ПравоОрбита».

PWA сохраняет интерфейс и заранее закешированные файлы. Текущий большой
SQLite-пакет текстов используется только нативным Expo-приложением, поэтому
в статической PWA без отдельного доступного API остаётся каталог реквизитов.
Подключать публичный API, переносить в web формат весь текстовый пакет или
публиковать правовые данные следует отдельным решением.

### Публикация в подключённый Cloudflare Worker

Текущий Cloudflare-проект использует **Workers Builds**, а не Cloudflare Pages.
В корне репозитория добавлен `wrangler.jsonc`: он публикует `mobile/dist/` как
статические файлы и возвращает `index.html` для внутренних маршрутов PWA.

В настройках Worker укажите:

```text
Root directory: пусто
Build command: npm run build
Deploy command: npm run deploy:cloudflare
Preview command: npx wrangler preview
```

Имя Worker в Cloudflare должно быть `ur-proect`, как в `wrangler.jsonc`. Если
в панели Cloudflare уже создан Worker с другим именем, замените только поле
`name` в этом файле на его точное имя до следующего деплоя.

Локально перед публикацией можно выполнить безопасную проверку без отправки
файлов в Cloudflare:

```powershell
Set-Location 'C:\Users\User\Documents\ChatGPT\консультант плюс ( с ИИ)'
npm run build
npm run verify:cloudflare
```

## Android: независимый APK

Один и тот же Expo-код уже поддерживает Android. В `mobile/eas.json` добавлен
профиль `preview`, который создаёт устанавливаемый APK без публикации в Google
Play и без постоянно работающего ноутбука.

Перед первой сборкой нужны только бесплатный Expo-аккаунт и вход в него. Вход
и первичная привязка проекта создаются один раз:

```powershell
Set-Location 'C:\Users\User\Documents\ChatGPT\консультант плюс ( с ИИ)\mobile'
npx eas login
npm run android:configure
```

После этого для создания нового APK используется одна команда:

```powershell
npm run android:apk
```

После завершения Expo даст ссылку на APK. Откройте её на Android-устройстве,
разрешите браузеру установку приложений из этого источника и установите APK.
Файл является самостоятельным Android-приложением; Expo Go и сервер помощника
для него не нужны.

Для Android-сборки также подготовлен `mobile/.easignore`: он передаёт в EAS
локальный SQLite-пакет текстов, хотя тот намеренно не хранится в Git из-за
размера. Поэтому APK, собранный с этого компьютера, включает текущую офлайн
библиотеку. Не удаляйте файл
`mobile/assets/legal/ru-core-snapshot-2026-09-25.db` до завершения сборки.

Не запускайте `eas build` без входа в свой Expo-аккаунт и не передавайте
созданную ссылку на APK посторонним, пока приложение не прошло нужные проверки.

## Чего пока нет

- PWA не опубликована: для этого нужен выбранный пользователем HTTPS-хостинг и
  вход в соответствующий аккаунт.
- iOS-приложение с собственной иконкой, независимое от Safari, требует Apple
  Developer Program и iOS-подпись.
- ИИ-помощник отключён от этих сценариев; публичный сервер не запускается.
