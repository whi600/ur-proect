# Архитектура «ПравоОрбиты»

## Граница первого этапа

Это технический каркас, а не правовая информационная система. В нём нет
полной базы правовых актов, аутентификации, оплаты, массовой загрузки внешних
источников или гарантии актуальности ответа. Контур для реальной модели
подготовлен, но до добавления владельцем серверных секретов она не вызывается.

В мобильном интерфейсе есть автономный каталог реквизитов Конституции, 20
кодексов и ключевых законов. Отдельно подготовлен сторонний снимок 37 текстов:
в нативном приложении — SQLite, в PWA — постраничные файлы. Он не выдаётся за
полный официальный реестр или проверенную действующую редакцию. Учебные
примеры остаются помеченными как демонстрационные.

## Компоненты

```text
PWA ──> встроенный каталог + постраничные статические тексты
  └──> Cloudflare Worker /api/assistant ──> Polza AI (только после секретов)

iPhone / Android (Expo Go) ──> локальный SQLite-снимок
  └──> тот же Worker для ИИ при наличии интернета

FastAPI /api/v1 (локальный демонстрационный контур)
  ├─ документы и простой поиск на demo данных
  └─ PostgreSQL / pgvector и юридически проверенный поиск (будущий этап)
```

Мобильное приложение знает лишь HTTP-контракт API. Никакой ключ поставщика ИИ,
пароль базы данных или внутренний URL БД в него не попадает. Публичная
переменная Expo используется только для адреса API; ключ модели хранится
исключительно в секретах Cloudflare Worker.

## Данные и редакции

Локальный файл `mobile/assets/legal/ru-core-catalog-v1.db` — это
metadata-only SQLite-пакет с FTS5-индексом. Он собран из версии манифеста,
проверяется скриптом и хранит только реквизиты. Отдельный source-snapshot
содержит неподтверждённые тексты; PWA загружает их небольшими файлами по
запросу, не замедляя начальную загрузку. Структура предусматривает проверенные
фрагменты, редакции, даты действия, источники и хеши, но юридическое ревью
этого снимка ещё не выполнено.

Миграция отделяет логический документ (`legal_documents`) от его редакций
(`document_versions`). Уже предусмотрены поля источника, URL источника,
лицензии, номера документа, публикации, редакции, даты начала/окончания
действия и хеша содержания. Это позволяет позже не подменять текст одной
редакции другой.

После выбора модели эмбеддингов отдельная миграция добавит фрагменты документа
и `vector(N)`. Размерность `N` намеренно не зафиксирована заранее: она зависит
от выбранной модели.

## Будущий ИИ-контур

Для реального ответа требуется следующий проверяемый поток:

```text
вопрос пользователя
  → уточнение юрисдикции, даты и обстоятельств
  → поиск кандидатов в лицензированных/официальных источниках
  → выбор редакции, действовавшей на нужную дату
  → выбор точных фрагментов с источниками
  → ответ с ссылками на фрагменты, ограничениями и уровнем уверенности
  → юридическая проверка качества и мониторинг ошибок
```

Модель должна получать только отобранные фрагменты и не должна заменять собой
источник права. Понадобятся: политика цитирования, журнал версий и источников,
оценка полноты поиска, набор юридически проверенных тестовых вопросов, ревью
юристом и процедура исправления ошибок. До этого ответы нельзя считать
юридической консультацией или достоверным изложением действующего права.

Перед приёмом будущего текстового пакета используется
`backend/scripts/validate_legal_package.py`. Он проверяет структуру,
HTTPS-источник, даты, хеши и фрагменты; юридическую полноту и актуальность он
не подтверждает — это обязанность редактора/юриста.

## Безопасность и сеть

`backend/.env` и `mobile/.env` игнорируются Git. Ключи ИИ разрешены только в
`backend/.env`; префикс `EXPO_PUBLIC_` для них запрещён. PostgreSQL в Compose
привязан к loopback-интерфейсу Windows и не публикуется в Wi-Fi или интернет.

Для теста телефона API можно слушать на `0.0.0.0:8000`, но правило Windows
Firewall должно быть точечным, только для входящего TCP 8000 в профиле Private.
Брандмауэр целиком не отключается. Expo tunnel помогает телефону получить
JavaScript-пакет приложения, но не публикует локальный FastAPI автоматически.
